# 资源与部署

本站使用同一代码库构建，可分别发布到公网和公司内网。页面内容、导航和静态资源保持一致，只有部署域名与可选基础路径不同。

## 地址入口

| 资源 | 公网地址 | 内网地址 |
| --- | --- | --- |
| gg-cli 文档站 | Vercel 域名待创建 | 内网域名/端口/路由待提供 |
| gg-ui 组件文档 | 待提供 | 待提供 |
| npm 包 | npm registry 中的包页面 | 如有内网 registry，待提供 |

<div class="gz-callout">
  <strong>发布前检查：</strong>确定以上四个文档地址后，替换本页与 gg-ui 页面中的“待提供”，再执行正式构建。
</div>

## 公网部署

推荐将本站连接到 Vercel，构建设置已经写入 `vercel.json`：

```text
Build Command: pnpm build
Output Directory: dist
```

Vercel 默认提供项目域名，也可以后续绑定公司自有域名。公网部署前应确认文档不包含：

- 内部账号、Token、真实接口地址和代理凭据。
- 未公开的业务数据、组织架构或客户信息。
- 只能在公司内部传播的仓库地址和排障信息。

## 内网部署

构建后将 `dist` 作为静态目录交给内网 Nginx、网关或静态资源服务器。

如果部署在域名根路径，直接执行：

```bash
pnpm build
```

如果部署在 `/frontend-docs/` 等二级路由，构建时设置相同基础路径：

```powershell
$env:DOCS_BASE='/frontend-docs/'
pnpm build
```

内网反向代理需要将该路由映射到 `dist`，并确保 HTML 路由可以回退到站点入口。

## 是否真的是“同一份资源”

两边使用同一套源码和内容。根路径不同的时候，会针对部署路径分别执行一次构建，以生成正确的资源前缀；这不是维护两套文档。

如果内外网都部署在域名根路径，则可以直接复用完全相同的 `dist` 目录。

## 推荐发布流程

```text
修改文档
  → 本地预览
  → pnpm build
  → 发布公网
  → 发布内网
  → 检查首页、搜索、导航和深层链接
```
