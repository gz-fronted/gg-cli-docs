# 项目特点

gg-cli 创建的不是一个空 React 工程，而是一套团队可以直接协作的项目基线。

## 创建后已经具备什么

| 能力 | 对开发者的帮助 |
| --- | --- |
| React、TypeScript、Vite | 直接开始页面开发，不必重新选择工具链 |
| micro-app、main-app 模板 | 统一 Garfish 主应用和微应用的接入方式 |
| gg-ui | 复用团队组件和主题，减少页面风格差异 |
| gz-pc | 统一接口请求、Hooks 和常用工具函数 |
| Mock | 后端接口未完成时也能独立开发 |
| 多环境构建 | 用明确命令构建开发、SIT 和生产环境 |
| 代码规范与测试 | 在提交前发现常见质量问题 |

## 推荐的开发方式

```text
页面放在 pages
  → 复用 gg-ui 组件
  → 接口封装到 api，并使用 gz-pc
  → 必要时补充 mock
  → 按项目规范完成检查与测试
  → 选择目标环境构建
```

团队统一的是基础设施和协作边界，具体业务页面、接口类型和状态模型仍由项目自行维护。

## 什么时候需要了解微前端细节

普通页面开发通常不需要修改 Garfish 入口。只有涉及以下内容时，再查看 [micro-app 模板](/templates/micro-app) 或 main-app 约定：

- 新增或修改微应用注册信息。
- 调整子应用激活路径或路由 basename。
- 使用主应用传入的 Token、主题或运行时状态。
- 修改挂载、更新、卸载生命周期。

## 模板会自动更新项目吗

不会。项目创建后独立维护，后续模板升级不会自动覆盖已有业务代码。大版本升级由项目团队评估后手动同步。
